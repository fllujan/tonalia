# Contribuir a Tonalia / Contributing to Tonalia

**Español:** ¡Gracias por querer ayudar! Puedes escribir issues y pull requests en español o en inglés. El código, los identificadores y los mensajes de commit van en inglés; la documentación de usuario, en los dos idiomas. Las secciones de abajo están en inglés porque describen el código.

**English:** Thanks for wanting to help! Issues and pull requests are welcome in Spanish or English. Code, identifiers and commit messages are in English; user documentation is in both languages.

---

## Ways to help

- **Report a bug or suggest a feature:** use the [issue templates](https://github.com/fllujan/tonalia/issues/new/choose). For a bug, include the Tonalia version (Settings → About) and the relevant lines of `engine.log` (Settings → About → "Open logs folder").
- **Test with real DJ software:** the checklists in [`docs/manual-tests.md`](docs/manual-tests.md) need people with Rekordbox, Serato, Traktor and VirtualDJ.
- **Improve the accuracy:** run `engine/tools/eval_key.py` or `eval_tempo.py` on your own tagged library and share the numbers (never the audio).
- **Translate or proofread** `app/src/i18n/{es,en}.json` and the docs.
- **Code:** pick an open issue, or open one first for a large change so we can agree on the approach.

## Ground rules

These are non-negotiable (see section 0 of [`SPEC.md`](SPEC.md)):

1. **Tonalia's own identity.** Never use another product's name, logo, colours, texts or screenshots. The 1A–12B notation is called **"Alphanumeric"** and the wheel is the **"Harmonic wheel"**: never use the trademarked name of that notation anywhere (UI, code, docs, commits).
2. **Everything local.** No accounts, telemetry or servers. The only network access allowed is the optional stem model download and the update check (which can be turned off).
3. **Never destroy user data.** Every write to a user's file or to another program's collection needs a backup, a simulation (preview), Undo and an atomic write.
4. **AGPL-3.0.** Every dependency must be compatible (see below). No "non-commercial" models or libraries.
5. **No copyrighted audio in the repository.** Test fixtures are generated by scripts (`engine/tests/fixtures/`). Evaluation datasets are downloaded to the git-ignored `datasets/` folder.
6. **Every visible string goes through i18n**, in Spanish and English. A test checks that both files have the same keys.
7. **Design:** [`DESIGN.md`](DESIGN.md) is the visual source of truth. Components use only the tokens in `app/src/styles/tokens.css`, never loose colours, and must keep WCAG AA contrast (checked by `styles/contrast.test.ts`).

## Development setup

You need [uv](https://docs.astral.sh/uv/), Node.js ≥ 20 with [pnpm](https://pnpm.io/), and stable [Rust](https://rustup.rs/). On Windows, also the Visual Studio C++ build tools that Tauri needs.

```sh
git clone https://github.com/fllujan/tonalia.git
cd tonalia

cd engine && uv sync --all-groups && cd ..   # Python 3.11 engine
cd app && pnpm install && cd ..              # Tauri 2 + React app
./scripts/fetch-binaries.sh                  # ffmpeg + rubberband (Windows: .ps1)
./scripts/gen-third-party                    # optional: the licence list in Settings → About

cd app && pnpm tauri dev
```

> On macOS, do not keep the repository in an iCloud-synced folder (Desktop or Documents): macOS blocks some writes from the build tools. `~/Developer/tonalia` works well.

Architecture in short (details in [`SPEC.md`](SPEC.md)):

```
app/src/          React + TypeScript UI (features/…, lib/rpc.ts, i18n/)
app/src-tauri/    Rust core: launches and supervises the engine, file dialogs
engine/           Python analysis engine, a JSON-RPC sidecar over stdio
scripts/          binaries, sidecar build, type generation, releases, licences
```

## Checks before every commit

The whole suite must pass. Never disable a test to make it pass.

```sh
# Engine
cd engine && uv run pytest
cd engine && uv run ruff check . ../scripts && uv run ruff format --check . ../scripts
cd engine && uv run mypy tonalia_engine tests tools

# App
cd app && pnpm lint && pnpm typecheck && pnpm test
cd app && pnpm test:e2e          # real UI + real engine, ~15 s

# Rust (on macOS, a CARGO_TARGET_DIR outside iCloud helps)
cd app/src-tauri && cargo clippy --all-targets -- -D warnings && cargo test
```

CI runs the same checks on macOS arm64, macOS x64 and Windows x64. It does not run on every push or pull request: it runs before each release and on demand (Actions → CI → Run workflow), so run the checks locally before opening a pull request.

## How changes are made

- **Tests first** for anything with logic: engine analysis, `keys`, `suggest`, `tags`, `export`. Coverage must stay ≥ 80 % in `keys.py`, `suggest.py`, `tags/` and `export/`.
- **`keys.py` and `app/src/lib/keys.ts` mirror each other** and share one JSON of test cases: change both together.
- **RPC types** are defined only in `engine/tonalia_engine/rpc_schema.py` (pydantic). After changing them, run `./scripts/gen-types` to regenerate `app/src/lib/rpc.types.ts`. CI fails if it is out of date. Never edit the generated file by hand.
- **Paths:** use `pathlib` in Python and Tauri's path APIs in Rust and TypeScript. Test paths with accents, emoji and spaces.
- **Small commits** in the [Conventional Commits](https://www.conventionalcommits.org/) style, in English: `feat(engine): add key ensemble`, `fix(app): keep the selection after sorting`.
- **User-facing changes** update the user guide ([`docs/user-guide.es.md`](docs/user-guide.es.md) and [`docs/user-guide.en.md`](docs/user-guide.en.md)).
- **Accuracy:** if you touch key or tempo detection, re-run the evaluation and update [`docs/accuracy.md`](docs/accuracy.md). Accuracy must not drop by more than 2 points.

## Adding a dependency

1. Check the licence is compatible with AGPL-3.0. Permissive licences (MIT, BSD, Apache-2.0, ISC, Zlib…), MPL-2.0, LGPL and GPL-2.0-*or-later*/GPL-3.0 are fine. GPL-2.0-*only*, "non-commercial" and proprietary licences are not.
2. Record it in [`docs/third-party.md`](docs/third-party.md) with its version range and licence.
3. The build runs `scripts/third_party.py`, which lists everything that ships in Settings → About → "Third-party licences" and in `THIRD-PARTY-NOTICES.txt`. It **fails** when a shipped package's licence is unknown or incompatible. If the package metadata is just unclear, read its licence file and add the package to `licenses/overrides.json`. For a bundled non-package component (like FFmpeg), add it to `licenses/bundled.json`.

## Pull requests

- Describe what changes and how you tested it. Add screenshots for UI changes, in light and dark mode.
- Keep the PR focused: one feature or fix.
- By contributing, you agree that your contribution is licensed under the [GNU AGPL-3.0](LICENSE), like the rest of Tonalia.
